# UI/UX 设计方针

虽然这只是一些笔记，但在此分享 VOICEVOX 的 UX 和 UI 设计方针。

## 基本方针

- 最重视的是“确保用户想要制作的内容能够顺利完稿”
- 基于这一理念，我们在设计时注重以下方面：
  - 让人产生想要使用的感觉
  - 工作流程一目了然
  - 操作时无需思考
- 同时，我们也重视“让用户创作出更优质的内容”
- 基于这一理念，我们还注重以下方面：
  - 能够轻松提高语音质量
  - 软件本身具有创造性

下面介绍这些理念具体是如何落实到实现中的。

- 让人产生想要使用的感觉
  - 为了尽可能覆盖更多用户，软件免费发布，并尽量保持高品质
  - 为了避免让人觉得“土气”，我们追求较新颖的外观设计
  - 为了不给未来用户留下负面印象，在社交媒体上谨慎表达负面情绪，并积极消除用户的负面疑问
- 工作流程一目了然
  - 注重首屏视图，让用户能从文本输入到语音导出一气呵成
  - 可有可无的功能尽量采用不显眼的 UI
- 操作时无需思考
  - 注重简洁的 UI
  - 避免使用难懂的词汇，力求文字简洁明了
  - UI 设计让用户即使不知道快捷键也能顺利操作
- 能够轻松提高语音质量
  - 首屏视图让用户能直观了解可以对语音进行调声

### 使命与软件方针的对应

- 我们认为，要实现[使命](./ミッション・バリュー・ビジョン.md#ミッション)，UGC（用户生成内容）是最重要的
  - 即用户创作的内容能拓展社区
- 基于这一理念，软件的方针是让更多优质内容被创作出来

## 设计决策流程

虽然仍在反复试错中，但大致按以下流程推进：

1. 在 Issue 等中提出设计方案的外观
   - 这是为了尽早发现考虑不周之处
   - 文本、手绘图、示例实现等均可
2. 实际实现并创建 Pull Request
   - UI/UX 设计有很多不实际试用就无法了解的部分，因此会以委托实现的形式进行
   - 设计变更即使代码量不大，内容也可能较多，因此将修改控制在 +/- 合计 80 行左右的差异内，合并会更顺畅
3. 梳理问题点
4. 合并
5. 查看整体设计，如有必要由维护者进行微调

## 详细设计指南

- 取消按钮在左侧
- 对话框与 Toast 的区分使用
  - 由用户操作引起、且属于错误或低频反馈的情况使用对话框（`SHOW_DIALOG_`系列）
    - 例：［需要重新启动引擎］引擎已停止，无法生成语音。是否重新启动引擎？［不重启/重启］
  - 其他情况使用 Toast 通知（`SHOW_NOTIFY_`系列）
    - 例：已导出语音。
    - 例：引擎异常终止。需要重新启动引擎。
- 关于对话框
  - warning 与 confirm 的区分使用
    - 预期用户希望继续操作时使用 confirm
    - 预期用户希望取消操作时使用 warning
  - 询问对话框的措辞
    - 标题使用疑问句“～しますか？”（是否～？）
    - 正文简洁明了，避免使用“よろしいですか？”（可以吗？）等表达
  - 错误对话框的措辞
    - 标题使用陈述句“〜に失敗しました。”（～失败。）
  - 按钮颜色
    - 表示肯定、且用户选择可能性较高的按钮使用 Primary 色
    - 具有破坏性、恢复状态需要花费精力的操作按钮使用 Warning 色

## 文案等

### VOICEVOX 专用 UI 名称

标有 🚷 的为尚未面向用户确定的名称（不在引导中使用）

关于具体对应哪个文件，请参照 [UI名称与Vue文件对应速查表](UI名称とVueファイル名の対応早見表.md)。

- 菜单 ･･･ 最上方的栏，包含文件、设置等项目
  - 固定按钮 🚷 ･･･ 关闭按钮附近、用于保持窗口最前方固定的功能
- 工具栏 ･･･ 菜单下方的栏，可自定义
- 角色显示区域 🚷 ･･･ 画面左侧的面板
- 脚本区域 🚷 ･･･ 包含文本栏等的面板
  - 轨道 🚷 ･･･ 包含一行文本的区域，面向用户时也可直接称为“文本栏”
    - 行号 ･･･ 轨道的编号，轨道名称面向用户后可改为“轨道编号”
    - 角色图标 ･･･ 可切换角色和风格的按钮
    - 文本栏 ･･･ 输入用于语音合成的文本的区域
  - 添加文本按钮 ･･･ 用于添加轨道的按钮
- 参数调整区域 🚷 ･･･ 画面右侧可调整参数等的面板
- 详细调整区域 🚷 ･･･ 画面下方可调整抑扬等信息的面板
  - 项目 ･･･ 详细调整区域中用于选择抑扬、重音等的按钮
  - 播放按钮 ･･･ 可播放语音的按钮
  - 重音区间 ･･･ 显示一个重音短语的区域（征求更好名称）
  - 逐字区间 🚷 ･･･ 重音区间中每个文字的显示区域，面向用户时可称为“逐字”
  - 读音 ･･･ 显示读音假名的区域

#### 其他 UI 部件

- 区域 ･･･ 视觉上被分隔开的位置
- 参数直接输入 🚷 ･･･ 点击参数可直接输入的区域，与普通文本显示无区别，因此没有单独名称
- 滑块 ･･･ 用于调整重音、语速等
- 选中的轨道/重音区间 🚷 ･･･ 处于活动状态的轨道/重音区间

### 其他概念的名称

- 向用户提示时使用“フォルダ”（文件夹）而非“ディレクトリ”（目录）
- 多引擎相关
  - 兼容 VOICEVOX API 的引擎称为“引擎”
    - 不确定是 VOICEVOX 引擎还是兼容引擎时称为“VOICEVOX 兼容引擎”
  - VVPP 文件直接称为“VVPP 文件”，如需说明则称为“VOICEVOX 兼容引擎包”
- 使用与 VOICEVOX 编辑器相同 UI 的软件总称为“VOICEVOX 系软件”
  - 正式名称为“VOICEVOX 系统 UI 软件”，因过长基本不使用

### 文体

- 字母使用半角
- 括号使用全角
  - 但括号内容全部为半角字符时，括号也使用半角
- 使用“です/ます”体（礼貌体）
- 项目名以名词结尾（体言止め）
- 按钮内文字使用“～する”（做～）

### Tooltip

- 句末加句号
- 句末附带括号时，句号放在括号外面
  - 例：このようにします（ただし注意が必要です）。
- radio 使用“选べます。”（可选择。）
- select 使用“変更できます。”（可更改。）
- button 使用“～できます。”（可～。）
- checkbox
  - ○○ 功能：“○○ 機能を有効にします。～～になります。”（启用 ○○ 功能。会变成～～。）
  - 默认 OFF 时：“ON の場合、～～れます/ません。”（设为 ON 时，会/不会～～。）
  - 默认 ON 时：“OFF の場合、～～れません/ます。”（设为 OFF 时，不会/会～～。）
