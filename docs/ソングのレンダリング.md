# 歌声的渲染

歌声的渲染（包括歌声合成API的调用等）通过 `RENDER` action 及其内部调用的 `SongTrackRenderer.render()` 执行。

## `songTrackRendering.ts` 中的主要类・类型说明

### `SnapshotForRender`（快照）

项目（轨道信息、项目设置等）的快照。
为了防止在渲染处理过程中原始数据被修改而导致数据不一致，在渲染开始前创建此快照，并基于该快照执行渲染。

### `PhraseForRender`（短语）

渲染的单位，包含音符及相关信息，以及渲染生成的中期和最终数据。
作为可变对象处理，在渲染过程中其属性会逐步更新。
短语是通过将轨道中的音符以休止符分割而生成的。

### `SongTrackRenderer`（歌声轨道渲染器）

负责管理歌声轨道整体渲染处理。

主要功能如下：

- **执行歌声轨道的渲染**  
  将歌声轨道的音符分割为多个短语，依次生成查询（音素时机）、歌声音高、歌声音量后，最终合成歌声。生成和合成按短语为单位进行，优先处理靠近播放头的短语。
- **缓存利用**  
  缓存已生成的查询、音高、音量和歌声，以加速重新渲染时的处理。
- **与外部引擎联动**  
  与歌声合成引擎联动，进行查询获取和歌声合成等操作。
- **事件通知**  
  在渲染的各个阶段（短语生成、缓存应用、歌声数据生成完成、错误发生等）发布事件，通知外部。
- **中断处理**  
  提供从外部中断正在进行的渲染处理的功能。

## 歌声渲染流程

当 `SingingStore` 的 `RENDER` action 被调用时，将执行以下处理。（请参照[流程图](res/ソングのレンダリングのフローチャート.md)）

1. 确认 `songTrackRenderer` 实例是否存在。
   - 若不存在，则调用 `SETUP_SONG_TRACK_RENDERER` action 来生成实例并注册事件监听器。
2. 确认渲染循环是否正在执行。
   - 若正在执行，则请求重新渲染（中断当前渲染并重新开始），然后结束 `RENDER` action。
   - 若未在执行，则请求开始渲染，并继续处理。
3. **执行渲染循环**  
   只要有渲染开始（重新开始）的请求且没有渲染停止的请求，就重复以下处理：
   1. **创建项目快照（`createSnapshot`）**  
      创建在渲染处理过程中可能被变更的数据（项目）的副本（快照）。
   2. **生成短语（`generatePhrases`）**  
      基于快照中的音符信息，生成作为渲染基本单位的短语（`PhraseForRender`）。短语通过以休止符分割音符生成。
      此时，短语尚不包含音频数据及其来源的详细参数。
      完成后，发布 `PhrasesGeneratedEvent` 事件。
   3. **提取可渲染的短语（`filterRenderablePhrases`）**  
      从所有生成的短语中，提取实际可渲染的短语（例如：属于已分配歌手的轨道的短语）。
   4. **应用缓存（`applyCachedDataToPhrases`）**  
      对于每个可渲染的短语，检查过去渲染结果（查询、歌声音高、歌声音量、歌声）是否存在于缓存中，若存在则加载并应用于短语。
      具体而言，对每个短语执行以下处理：
      1. **应用查询缓存**
         - 若查询缓存存在，则加载并应用于短语。
         - 若查询缓存不存在，则继续处理下一个短语的缓存加载。
      2. **应用歌声音高缓存**
         - 若歌声音高缓存存在，则加载并应用于短语。
         - 若歌声音高缓存不存在，则继续处理下一个短语的缓存加载。
      3. **应用歌声音量缓存**
         - 若歌声音量缓存存在，则加载并应用于短语。
         - 若歌声音量缓存不存在，则继续处理下一个短语的缓存加载。
      4. **应用歌声缓存**
         - 若歌声缓存存在，则加载并应用于短语。

      完成后，发布 `CacheLoadedEvent` 事件。

   5. **提取需要渲染的短语（`filterPhrasesRequiringRender`）**  
      即使应用了缓存，仍缺少查询、歌声音高、歌声音量、歌声中任意一项的短语，即为实际需要渲染的短语。提取这些短语。
   6. **渲染各个短语**  
      只要存在未处理（未渲染）的短语且没有中断请求，就重复以下处理：
      1. **选择要渲染的短语（`selectPriorPhrase`）**  
         从等待渲染的短语组中，选择最接近当前播放头位置的短语作为下一个处理对象。
      2. **渲染短语（`renderPhrase`）**  
         对所选短语依次执行以下处理：
         1. 发布 `PhraseRenderingStartedEvent` 事件。
         2. **生成查询（音素时机）**
            1. 若查询尚未生成，则调用引擎API（`engineSongApi.fetchFrameAudioQuery`）生成查询。
            2. 生成后，将结果保存至缓存并应用于短语。
            3. 发布 `QueryGenerationCompleteEvent` 事件。
         3. **生成歌声音高**
            1. 若歌声音高尚未生成，则调用引擎API（`engineSongApi.fetchSingFrameF0`）生成歌声音高。
            2. 生成后，将结果保存至缓存并应用于短语。
            3. 发布 `PitchGenerationCompleteEvent` 事件。
         4. **生成歌声音量**
            1. 若歌声音量尚未生成，则调用引擎API（`engineSongApi.fetchSingFrameVolume`）生成歌声音量。
            2. 生成后，将结果保存至缓存并应用于短语。
            3. 发布 `VolumeGenerationCompleteEvent` 事件。
         5. **合成歌声**
            1. 若歌声尚未生成，则调用引擎API（`engineSongApi.frameSynthesis`）合成歌声。
            2. 生成后，将结果保存至缓存并应用于短语。
            3. 发布 `VoiceSynthesisCompleteEvent` 事件。
         6. 短语渲染完成后，发布 `PhraseRenderingCompleteEvent` 事件。
            若短语渲染过程中发生错误，则发布 `PhraseRenderingErrorEvent` 事件，并继续处理下一个短语。
